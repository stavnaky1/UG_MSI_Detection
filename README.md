# UG_MSI_Detection

[![Reference data DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23160540.svg)](https://doi.org/10.5281/zenodo.23160540)
<!-- TODO(stav): after the first GitHub release is archived by Zenodo, add the code DOI badge here. -->

Homopolymer-indel features for microsatellite instability (MSI) detection from
Ultima Genomics (UG) somatic VCFs.

This repository accompanies a research paper in review, and the README will be updated once published.

## What it does

Mismatch-repair deficiency leaves replication slippage errors at mononucleotide
repeats, predominantly 1-bp deletions. `hmer_indel_summary.py` measures this in
UG somatic VCFs: for every VCF in a directory, it filters to high-confidence somatic
indels inside a genomic territory (whole-genome HCR or padded exome) and reports
counts and fractions of homopolymer indels (h-indels), including 1-nt deletions in
long (10–15 bp) homopolymers.

The output is one row of features per sample.


## Installation

```bash
git clone https://github.com/stavnaky1/UG_MSI_Detection.git
cd UG_MSI_Detection
conda env create -f environment.yml
conda activate ug_msi
```

Dependencies: Python 3 (tested with 3.12), numpy, pandas, and `bcftools` on `PATH`
(`bgzip`/`tabix` from htslib to prepare inputs). `environment.yml` pins the versions
the example was verified with.

```bash
bash example/run_example.sh
```

This runs the tool on two small **synthetic** VCFs (an MSI-like and an MSS-like
profile, generated by `example/make_toy_data.py`) and checks the result against
`example/expected_output.csv`. It takes a few seconds and ends with

### gnomAD allele-frequency table

VCFs that lack `INFO/GNOMAD_AF` are annotated from a table passed with
`--gnomad_tsv`. It must be bgzipped and tabix-indexed, with five columns
(no header): `CHROM POS REF ALT AF`, and **it must contain indels**, because matching
is on exact `REF`/`ALT` and the tool only analyzes indels. A table can be built from
gnomAD sites VCFs, for example:

```bash
# one chromosome per file, each already position-sorted; split multiallelic
# sources first with `bcftools norm -m -any` if needed
for f in gnomad.genomes.*.sites.chr*.vcf.bgz; do
  bcftools query -f '%CHROM\t%POS\t%REF\t%ALT\t%INFO/AF\n' "$f"
done | bgzip > gnomad_af.tsv.gz
tabix -s1 -b2 -e2 gnomad_af.tsv.gz
```

## Input VCFs

Each `*.vcf.gz` in `--path_with_vcfs` must be:

- a **single-sample** somatic VCF from the Ultima Genomics pipeline
  (TODO(stav): pipeline name/version), bgzipped and indexed (`.tbi` or `.csi`);
- annotated with `INFO/VARIANT_TYPE` (`h-indel` / `non-h-indel` / `snp`),
  `INFO/X_HIL` (homopolymer length), `INFO/X_HIN` (homopolymer nucleotide) and
  `FORMAT/VAF`;
- on the same contig naming as the BED.

The tool checks these up front and stops with a message naming the offending file.
Multi-sample (e.g. tumor–normal) VCFs are skipped with a warning; extract the tumor
sample first (`bcftools view -s TUMOR`).

## Usage

```bash
python hmer_indel_summary.py \
    --bed_for_intersect refs/ug_hcr.v1.4.bed \
    --path_with_vcfs    path/to/vcfs \
    --output_dir        path/to/vcfs_wgs_out \
    --gnomad_tsv        refs/gnomad_af.tsv.gz
```

Run once per territory (HCR for WGS-equivalent, padded exome for WXS-equivalent).
The defaults reproduce the published analysis.

| Option | Default | Meaning |
|---|---|---|
| `-b, --bed_for_intersect` | required | BED territory |
| `-v, --path_with_vcfs` | required | Directory of input `*.vcf.gz` |
| `-o, --output_dir` | required | Cache + summary directory (must differ from the input directory) |
| `-g, --gnomad_tsv` | none | AF table; needed only if some VCFs lack `INFO/GNOMAD_AF` |
| `--min_qual` | 16 | Minimum `QUAL` |
| `--max_hmer_length` | 15 | Records with `X_HIL` above this are removed |
| `--min_long_hmer_length` | 10 | `X_HIL` threshold for a "long" h-indel |
| `--gnomad_af_threshold` | 0.01 | Keep `GNOMAD_AF` < threshold, or absent |
| `--max_vaf` | 0.5 | Keep `VAF` ≤ threshold (missing VAF is removed) |
| `--at_only` | off | Restrict to A/T homopolymers |
| `-t, --threads` | 8 | bcftools threads |

## Processing steps

1. **Prefilter (bcftools, cached).** Records overlapping the BED (`bcftools view -R`),
   `FILTER=PASS`, indels only, `QUAL ≥ min_qual`, `ID == "."` (no known-variant ID),
   `X_HIL ≤ max_hmer_length`.
2. **gnomAD annotation.** If the prefiltered VCF has no `INFO/GNOMAD_AF`, it is added
   from `--gnomad_tsv` by exact `CHROM, POS, REF, ALT` match.
3. **Filters (pandas).** Step 1 is re-applied, and additionally: multiallelic records
   removed, `GNOMAD_AF < gnomad_af_threshold` or absent, `VAF ≤ max_vaf`.
4. **Measurement.** Counts below, computed on the records that pass step 3.

`bcftools view -R` keeps records whose REF allele overlaps a BED interval even if
`POS` lies just outside it. Overlap semantics have changed across bcftools versions,
so use the pinned version when reproducing published numbers.

## Output

`<output_dir>/<input dir name>_<tag>_hmer_indel_summary.csv`, one row per VCF.
Percentages are on a 0–100 scale; a value is empty (NaN) when its denominator is 0.

| Column | Definition |
|---|---|
| `vcf`, `vcf_path` | Filtered VCF the row was measured on (name starts with the input VCF name) |
| `n_records_in_bed` | Records after the step-1 prefilter (not all records in the BED) |
| `n_records_after_filters` | Records after step 3 |
| `Total indels` | h-indels + non-h-indels after step 3 |
| `h-indels`, `% h-indels` | `VARIANT_TYPE == h-indel`; % of total indels |
| `1nt del`, `% 1nt del` | 1-nt deletions among h-indels; % of total indels |
| `2nt del`, `1nt ins` | 2-nt deletions and 1-nt insertions among h-indels |
| `Long h-indels`, `% Long h-indels in all indels` | h-indels with `min_long_hmer_length ≤ X_HIL ≤ max_hmer_length`; % of total indels |
| `1nt del in long hmers` | 1-nt deletions among long h-indels |
| `% 1nt del in long hmers` | … as % of long h-indels |
| `% 1nt del in long hmers of all indels` | … as % of total indels |
| `1 nt del / 1 nt ins`, `2 nt del / 1 nt ins` | Ratios among h-indels (NaN if no 1-nt insertions) |

### Caching

Prefiltered and gnomAD-annotated VCFs are written to `--output_dir` and reused on
later runs. File names encode the BED stem, `min_qual`, `max_hmer_length` and
`at_only`, so changing those creates new files. Changing the gnomAD table, or
reusing one output directory for two input directories with overlapping VCF names,
does **not** invalidate the cache: use a fresh output directory in those cases.
